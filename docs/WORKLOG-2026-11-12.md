# 2026-11-12 작업기록

## 1. 사용자 요청과 확정 사항

- 실행 환경은 **Windows**로 확정했다.
- 사용자에게 수집 방식 선택지를 제공한다. 로그인 전 메뉴 파악과 로그인 후 메뉴 파악을 나누고, 방식마다 필요한 정보만 입력받는다.
- 실행 형태는 웹 UI보다 **CLI 스크립트**를 선호한다. 흐름은 "URL 입력 → 선택지 → 진행"이다.
- 최종 목적은 **사이트 하위 메뉴를 정리해 진단표에 넣는 것**이다. 진단표는 실제로는 **구글 시트**다.

## 2. 구현 내용

### 수집 방식 (`models.py`, `crawler.py`)

| 방식 | 흐름 |
|---|---|
| `public` 로그인 전 | 브라우저를 열고 바로 수집한다. 화면 없이 실행(`--headless`)도 가능하다 |
| `login` 로그인 후 | 로그인 페이지를 열고, 사용자가 로그인한 뒤 Enter를 누르면 수집한다 |
| `compare` 전·후 비교 | 공개 메뉴를 수집하고, 로그인한 뒤 다시 수집한다. 메뉴마다 노출 구분을 붙인다 |

- `Menu.seen`에 메뉴를 발견한 단계(before, after)를 기록한다. 비교 방식에서만 `로그인 전 공개`와 `로그인 후 전용`을 표시한다.
- `Menu.status_before`에 로그인 전 방문 상태를 남긴다. 예를 들어 로그인 전에는 `로그인 필요`였던 페이지가 로그인 후 `수집됨`이 된 것을 확인할 수 있다.
- 확인 필요 항목에 `phase`와 `resolved`를 붙였다. 같은 단계를 재수집하면 그 단계의 경고만 교체하고, 로그인 후 해결된 로그인 전 경고는 `로그인 후 수집됨`으로 표시한다. 전날 남긴 "재수집 시 이전 경고 처리" 검토 항목을 이렇게 해결했다.
- 로그인 후 수집을 시작할 때 비밀번호 입력란이 아직 보이면 경고한다. 방문 페이지의 30% 이상이 로그인 화면이면 세션 만료 가능성을 경고한다.
- `fill_login`은 보이는 비밀번호 입력란과 그 앞의 아이디 입력란을 채운다. **제출은 하지 않는다.** 값은 명령 큐에서 한 번만 쓰고 report, 기록, 엑셀에 남기지 않는다.
- `MENU_CRAWLER_BROWSER_PATH`로 Chromium 실행 파일을 지정할 수 있다.

### CLI (`menu_crawler/cli.py`, `run.bat`)

- 옵션 없이 실행하면 URL, 수집 방식, 대상 이름, 로그인 주소, 고급 설정, 권한 확인을 차례로 묻는다.
- 같은 내용을 옵션으로 줄 수 있다: `URL --mode --login-url --username -y --headless --max-pages ...`
- 로그인 단계 메뉴: Enter(수집 시작), `a`(자동 입력, 비밀번호는 getpass로 받음), `o`(로그인 화면 다시 열기), `c`(현재 화면 메뉴 추가), `q`(종료).
- 진행률을 한 줄로 표시한다. Ctrl+C를 누르면 정상 중지한 뒤 그때까지의 결과를 저장한다.
- 결과 요약으로 상태별 개수, 노출 구분, 확인 필요 상위 5건, 메뉴 트리 미리보기(★ = 로그인 후 전용)를 보여 준다.
- `결과\` 폴더에 엑셀을 저장한다.

### 구글 시트 붙여넣기

- 1·2·3 Depth를 3행으로, 메뉴를 가로로 배치한 TSV를 250개 단위로 만든다. 진단표 H13에 Ctrl+V 하면 H13:15에 들어간다.
- Windows에서는 PowerShell `Set-Clipboard`로 묶음마다 클립보드에 복사한다. `.tsv` 파일도 함께 저장한다.
- `= + - @`로 시작하는 값에는 `'`를 붙여 수식으로 해석되지 않게 한다.

### 엑셀 (`export.py`)

- 요약 시트에 수집 방식, 완료 단계, 노출 구분 개수를 추가했다.
- 비교 방식일 때 `전체메뉴` 시트에 `노출 구분`과 `로그인 전 상태` 열을 추가한다. `로그인후_전용메뉴` 시트도 만든다.
- `미수집_확인필요` 시트에 `수집 단계`와 `해결 여부` 열을 추가했다.

### 웹 화면 (보조)

- CLI로 방향을 정하기 전에 단계형 웹 화면(`static/`)을 만들었다. 지우지 않고 `run_web.bat` 보조 실행 방식으로 남겼다. 로컬 API에 `/api/control/login`, `/api/login/fill`, 단계 지정 수집을 추가했다.

### Windows 배치파일

- `install.bat`: Python 3.10 이상인지 확인하고 `.venv`를 만든 뒤 의존성을 설치한다. Edge나 Chrome이 없을 때만 내장 Chromium을 설치한다.
- `run.bat`: CLI를 실행한다. 설치가 안 돼 있으면 `install.bat`을 먼저 실행한다.
- `run_web.bat`, `install_browser.bat`
- `.gitattributes`로 배치파일을 CRLF로 고정했다. 모두 UTF-8에 `chcp 65001`을 쓴다.

## 3. 검증

- `pytest`: **17개 통과** (`MENU_CRAWLER_BROWSER_PATH=/opt/pw-browsers/chromium`). 이 클라우드 환경은 Playwright 1.65와 설치된 Chromium 버전이 맞지 않아, 경로를 지정하지 않으면 브라우저 테스트 3개가 실행되지 않는다.
- 로컬 시험 사이트(쿠키 로그인, 중첩 메뉴, 로그인 전용 메뉴, 로그아웃 링크)로 비교 방식 전체 흐름을 검증했다.
  - 로그인 전에는 `거래내역`이 보이지 않았고, 로그인 후 `로그인 후 전용`으로 수집됐다.
  - `마이페이지`는 로그인 전 `로그인 필요`였고 로그인 후 `수집됨`이 됐다. 해당 경고는 `로그인 후 수집됨`으로 표시됐다.
  - 로그아웃 링크는 방문하지 않았다(`동작 확인 필요`). 로그인 세션도 유지됐다.
  - 비밀번호는 report와 엑셀 어디에도 남지 않았다.
- 대화형 CLI에 입력을 넣어 같은 흐름을 실행했다. 메뉴 트리, 엑셀, TSV 출력을 확인했다.
- **미검증:** Windows 실기(배치파일, 클립보드, Edge 실행), 실제 대상 사이트, 웹 화면의 브라우저 클릭 흐름.

## 4. 자가개선 3회

| 회차 | 점검 결과 | 조치 |
|---|---|---|
| 1. 안정성 | 로그인 후 수집이 로그인 전 방문기록을 지움. about:blank 프레임 경고 노이즈. CLI가 메시지 변화로 명령 완료를 판단해 같은 메시지면 15초 대기. Ctrl+C 시 결과 미저장. 아이디 칸이 헤더 검색창으로 잡힐 수 있음 | 방문기록을 단계별로 보존. 웹 문서가 아닌 프레임 무시. 명령 티켓(issued/completed) 방식. 중단 시 부분 저장. 같은 form 안에서 비밀번호 앞의 보이는 입력란 선택 |
| 2. 메뉴 정리 품질 | 국내 사이트형 샘플에서 `본문 바로가기`·`맨 위로`가 메뉴로 잡힘. LNB 복사본이 1 Depth로 중복. 약관·회원가입이 확인 필요 목록을 채움. 늦게 발견한 메뉴가 맨 뒤로 감 | 페이지 내 앵커 제외(SPA `#/` 유지). LNB/SNB의 보이는 제목을 상위 메뉴로 사용(숨김 `주메뉴` 제외). 헤더 유틸·푸터는 `공통 링크`로 분류해 검토 목록에서 제외. 트리 순서 정렬 |
| 3. Windows | Ctrl+C가 브라우저 드라이버까지 종료시킬 수 있음. 엔진 오류 시 `sys.exit`으로 부분 결과 유실. PowerShell 클립보드는 정책 차단·경로 따옴표·끝 개행 문제. 진행 줄 110자 고정. 결과 파일 덮어쓰기, 엑셀에서 열린 파일 저장 실패 | `q` 키 안전 중지(msvcrt). 오류 시에도 부분 저장. Win32 API(CF_UNICODETEXT) 클립보드 우선, PowerShell은 대체. 창 너비 기준 출력. 초 단위 파일명과 중복 번호, 잠긴 파일은 다른 이름으로 저장 |

검증: Python 3.13과 3.10 모두 pytest 24개 통과. Win32 클립보드와 `q` 키 중지는 Windows 전용이라 이 환경에서 실행하지 못했다.

## 5. 진단 엑셀 직접 입력 (menu_crawler/workbook.py)

- 목표: 수집한 메뉴를 진단 양식의 진단 시트 13~15행(H~IW)에 넣는 것.
- 양식 손상 방지: openpyxl로 저장하면 차트가 사라지므로 시트 XML의 해당 칸만 inlineStr로 수정한다. 대상 시트와 workbook.xml(fullCalcOnLoad) 외의 파트는 바이트 그대로 복사한다.
- 데이터 보호: 13~15행이나 20~67행에 값이 하나라도 있는 열은 사용하지 않는다. 같은 메뉴 경로는 건너뛴다. 원본을 덮어쓰지 않는다. 250열을 넘는 메뉴는 TSV로 남긴다.
- CLI: 크롤링 뒤 대화형으로 묻는다. `--workbook`, `--sheet`, `--workbook-out`, `--from-result` 옵션을 쓸 수 있다.
- 검증: pytest 28개 통과. 실제 진단 양식에 메뉴 6개를 넣었을 때 엑셀 수준 엔진(LibreOffice)과 구글 시트 모두 16행 경로, 등록 메뉴 수, 사이트목록, 종합현황 상태가 갱신되고 오류 0이었다. 실제 양식은 고객 정보가 있어 저장소에 넣지 않았다.

### 진단 시트 입력 자가개선 3회

| 회차 | 점검 결과 | 조치 |
|---|---|---|
| 1. 안정성 | 메뉴명에 제어 문자가 있으면 저장이 멈춤, .xlsm 양식 거부, 결과 파일이 아닌 파일을 조용히 0개로 처리 | 제어 문자 제거, .xlsm 지원(확장자 유지), 저장 후 다시 열어 모든 칸 검증(다르면 파일을 만들지 않음), 잘못된 결과 파일 경고 |
| 2. 메뉴 누락 | 메뉴 구조에서 이름은 확인했지만 로그인·권한·접속 실패·탐색 제한으로 확인하지 못한 메뉴가 진단 시트에서 빠짐 | 대화형에서 포함 여부를 물음(기본 예), `--include-unverified`. 본문 링크·로그아웃·파일 링크는 제외 |
| 3. 사용성 | 시트 이름을 정확히 입력해야 함, 무엇을 넣었는지 기록이 없음, 질문 순서가 어색함 | 시트 목록에 기존 메뉴·빈 칸 표시, `--sheet`를 번호나 이름 일부로 지정, 저장 전 미리보기, `_입력내역.tsv`(입력·이미 있음·칸 부족), 저장 후 열기, 질문 순서 정리 |

## 6. 구글 시트 기입 흐름

- 배경: 진단표 작성은 구글 시트에서 하므로 엑셀 파일 직접 입력만으로는 기입까지 이어지지 않는다.
- 흐름: 크롤링 → 결과 엑셀 저장 → "어디에 기입할까요?"(구글 시트 붙여넣기 / 엑셀 파일 / 건너뛰기).
- 구글 시트 붙여넣기: 구글 시트를 .xlsx로 받은 스냅숏(선택)을 읽어 메뉴·결과가 있는 마지막 열 다음 칸을 시작 칸으로 계산하고, 이미 있는 메뉴 경로는 뺀다. "시트의 AI13 클릭 → Ctrl+V"처럼 칸과 채워지는 범위를 안내하고, 3행×N열 TSV를 클립보드와 파일로 남긴다. 스냅숏 파일은 읽기만 한다.
- 옵션: `--target google|excel`, `--snapshot`. 비대화형(`-y`)에서 `--workbook`이 없으면 구글 붙여넣기로 진행한다.
- 검증: pytest 33개 통과. 실제 진단표 스냅숏에서 메뉴 27개가 있는 시트는 AI13, 빈 시트는 H13으로 안내했다.

## 7. 작업 엑셀 중심 흐름 · 여러 진단 대상 · 구글 시트 자동 입력

- 흐름: 작업 엑셀 붙여넣기 → 점검 주소 입력(여러 개) → 대표 도메인(D6)으로 진단 시트 자동 매핑, 없으면 대상 이름으로 지정 → 수집 방식(기본: 로그인 후) → 대상마다 수집·결과 저장·기입 → 결과 표.
- 엑셀 기입: 여러 대상을 하나의 새 파일에 차례로 넣는다. 실제 양식 사본에서 바뀐 부분은 대상 시트의 메뉴 칸 4개와 workbook.xml 재계산 플래그뿐이고, 셀 서식 번호·병합·조건부 서식·데이터 유효성·틀 고정은 동일했다. 새로 만드는 칸은 열 서식을 이어받는다.
- 구글 시트 자동 입력: `apps_script/MenuImport.gs`(웹 앱) + `menu_crawler/gsheet.py`. 미리보기(dryRun) → 확인 → 입력, 문서 잠금, 값만 입력(`'` 접두로 수식·날짜 변환 방지), 연결 키 검사.
- 화면: 단계 표시, 한글 폭 맞춤 표, 색상(Windows 10 콘솔 지원, NO_COLOR 존중).
- 검증: pytest 40개(JS 계획 로직 포함) 통과. 구글 시트 실배포는 사용자 시트에서 확인 필요.

## 8. Windows 실행 피드백 반영

- 증상: Windows 콘솔(chcp 65001)에서 `━ · ※ …` 같은 폭 모호 문자가 한 칸으로 잡히고 두 칸으로 그려져 입력 줄과 겹쳤다.
- 조치: 콘솔 출력만 ASCII로 바꾸는 계층(ui.plain/ConsoleText), 구분선 ASCII, 줄 폭을 콘솔 폭-1 이하로 제한, 진행 줄도 폭 맞춤.
- 편의: 시트 목록을 여러 열로 압축, `?`로 목록 다시 보기, D6이 비어 있으면 점검 주소 기록 여부 질문, D6에 주소 여러 개 허용, 미확인 메뉴 포함 질문은 한 번만, 중단 시 부분 결과 기입 확인과 결과 표, 끝나면 진단 엑셀 열기.
- 검증: pytest 43개 통과, 실제 양식 사본으로 전체 흐름 재실행(29번 시트 H13:J15 + D6 기록).

3. 필요하면 구글 시트 API로 시트에 바로 쓰는 기능을 검토한다. 서비스 계정이나 OAuth 설정이 필요하다.
