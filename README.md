# Web Menu Crawler

웹사이트의 실제 메뉴 구조를 **1·2·3 Depth까지 수집하고 엑셀로 정리**하는 로컬 프로그램입니다.

> **현재 상태: 개발 버전(v0.3).** 작업 엑셀 → 진단 대상 선택 → 수집 → 진단 시트 기입까지 한 번에 동작합니다. 로컬 시험 사이트와 실제 진단 양식 사본으로 검증했고, Windows에서 실행 화면을 확인했습니다. **실제 로그인 대상 사이트 검증은 진행 중입니다.**

## 빠른 사용법 (Windows)

1. Python 3.10 이상을 설치합니다. 설치할 때 "Add python.exe to PATH"를 체크합니다.
2. `install.bat`을 더블클릭합니다. 최초 1회만 합니다. (업데이트: `git pull`)
3. `run.bat`을 더블클릭하고 질문에 답합니다.

**기본은 구글 시트 진단표**입니다. [구글 시트 연결](#구글-시트-자동-입력-연결-처음-1회)을 한 번 해 두면 첫 질문에서 Enter만 누르면 구글 시트의 진단 시트에 값만 바로 입력합니다. 엑셀 파일로 하려면 그 자리에 파일을 끌어다 놓습니다.

```
[1/3] 진단표             Enter = 구글 시트(연결됨) | 엑셀 파일 끌어다 놓기 | p = 붙여넣기 | - = 수집만
[2/3] 진단 대상          대상: 29-34, 36, 41        <- 시트 번호/범위: 각 시트 D6(대표 도메인) 주소로 수집
                         대상: 사이트A               <- 시트 이름 일부
                         대상: 전체                  <- D6이 적힌 시트 모두
                         대상: https://app.example.com  <- 주소: D6과 비교해 시트를 찾음
                         추가 대상: (Enter로 끝)
[3/3] 수집 방식          1) 자동 (기본)  2) 로그인 전  3) 로그인 후  4) 로그인 전/후 비교
-> 작업 순서 확인 (대상별 기존 메뉴 수, 접속 확인 결과) -> 시작
-> 대상마다 차례로: 브라우저 열기 -> 로그인 -> 수집 -> 메뉴 목록 엑셀 저장 -> 진단 시트 기입
-> 작업 결과 표 + 결과\작업기록_날짜.tsv
```

**진단 대상 지정**
- 번호는 시트 앞 번호(`01_…`)입니다. `01-05`처럼 범위, `1 2`처럼 띄어 쓴 여러 번호, 쉼표 구분을 모두 받습니다. 같은 시트·주소는 한 번만 넣습니다.
- **D6 셀(대표 도메인)**을 기준으로 매핑합니다(`www.`·http/https 무시, 포트는 구분). 개발망처럼 하위 주소로 접속해도 찾도록 단계별로 비교합니다.

  | 단계 | 예 (D6 → 점검 주소) | 처리 |
  |---|---|---|
  | 같은 호스트, D6 경로 아래 | `a.com` → `a.com/global.app/login.do` | 자동 |
  | 같은 호스트, 점검 주소가 D6보다 위 | `a.com/global.app` → `a.com/` | 자동(후보가 여럿이면 선택) |
  | 같은 호스트, 경로만 다름 | `a.com/bank` → `a.com/card` | 확인 후 |
  | D6이 상위 도메인 | `example.com` → `dev.example.com` | 확인 후 |

  `/index.jsp`, `/main.do` 같은 페이지 파일은 경로에서 빼고 비교하며, `/global.app` 같은 컨텍스트 경로는 그대로 비교합니다. 같은 호스트에 다른 진단 시트가 있으면 그 시트의 D6 경로 아래만 수집합니다. D6에는 주소를 여러 개 적을 수 있고(줄바꿈·쉼표·공백), 각 주소를 차례로 수집해 같은 시트에 이어서 넣습니다. 메모(`(운영)`, `예) …` 등)는 무시합니다.
- 사이트목록 시트의 대표 도메인 열은 D6을 보여 주는 수식입니다. **각 진단 시트 D6에 적습니다.**
- D6이 비어 있는 시트는 점검 주소를 물어보고, D6에 적어 둘지 묻습니다(다음부터 번호만으로 수집). 일치하는 시트가 없는 주소는 이름으로 지정하거나 Enter로 뺍니다. `?` = 시트 목록.

**기입 규칙 (값만 입력)**
- 진단 시트 13~15행(1·2·3 Depth)에서 **마지막으로 쓴 열의 다음 칸부터** 메뉴명만 넣습니다. 중간의 빈 열, 숨긴 열, 병합 셀, 수식 칸, 결과 칸(20~67행), 서식, 다른 시트는 건드리지 않습니다.
- 시트에 이미 있는 메뉴 경로는 건너뜁니다. 같은 파일로 다시 돌리면(추가 조사) **새 메뉴만** 이어서 넣습니다.
- 원본은 그대로 두고 `원본이름_메뉴입력_날짜.xlsx` 하나에 대상들을 차례로 기입합니다. 결과 파일이 엑셀에서 열려 있으면 닫고 다시 시도할지 묻습니다.

**수집 방식**
- **1) 자동(기본)**: 로그인 없이 먼저 수집하고, 로그인 화면만 보이는 대상(로그인 기능 말고 메뉴가 거의 없음, 또는 로그인 화면으로 넘어감)은 그 자리에서 로그인 단계로 넘어갑니다. 브라우저 창에서 로그인하고 Enter를 누르면 로그인 후 메뉴를 수집합니다. 공개 메뉴가 보이는 대상은 로그인 없이 끝납니다.
- 2) 로그인 전만, 3) 로그인 후만, 4) 전·후 비교(로그인 후에만 보이는 메뉴 구분)는 모든 대상에 같은 방식이 필요할 때 고릅니다. 공개 사이트라도 로그인 후 메뉴(계좌조회 등)까지 시트에 필요하면 4를 고릅니다.
- 로그인 기능(`Login > Forgot User ID …`)은 로그인 전 화면에서 읽어 맨 앞에 두고, 로그인 후 메뉴를 이어서 넣습니다.

**수집**
- 페이지 수·시간 제한이 없습니다. 메뉴를 모두 확인하면 끝나고, 토큰·시각 값만 바뀌는 같은 페이지는 3번까지만 방문합니다. 중간에 멈추려면 **`q`** (그때까지 결과 저장, 기입 여부 질문).
- **로그인할 창**(로그인이 들어가는 방식에서 고름):
  - 1) 수집기 창(기본): 아이디/비밀번호, 문자·앱 OTP.
  - 2) **내 브라우저 창**(`--my-browser`): 공동·금융인증서, 키보드 보안 같은 보안 프로그램, 자동화 창을 막는 사이트. 수집기가 Edge/Chrome을 자동화 표시 없이 **보통 브라우저로** 열고(수집기 전용 프로필 `browser_profile/`, 보안 프로그램·확장은 한 번만 설치), 그 창에 새 탭을 붙여 로그인 상태 그대로 수집합니다. 끝나면 수집기 탭만 닫고 브라우저와 다른 탭은 그대로 둡니다. 로그인이 유지되는 동안 같은 사이트는 다시 로그인하지 않아도 됩니다.
- 로그인 단계: 브라우저 창에서 직접 로그인 후 Enter. `a` = 아이디/비밀번호 자동 입력(로그인 버튼·보안문자·OTP는 직접). 같은 계정을 다음 대상에도 채울지 묻고, 허용하면 **이번 실행 동안 메모리에만** 보관합니다(파일·엑셀·기록에 저장하지 않음).
- 시작 전에 대상별 접속을 확인해 VPN·사내망·주소 문제를 미리 알려 줍니다. 개발 서버의 자체 서명 인증서는 허용합니다.
- 수집에 실패한 대상(접속 불가 등)은 기입하지 않고 '수집 실패'와 사유를 남깁니다. 대상 사이에서 `s` = 건너뛰기, `q` = 여기서 끝내기. 결과 표 다음에 **실패·건너뛴 대상만 바로 다시 시도**할지 묻습니다.
- 로그인 단계에서 계정 문제 등으로 로그인이 안 되면 `p` = 로그인 없이 공개 메뉴만 수집합니다.
- 로그인 후 수집 중에 연속으로 로그인 화면이 나오면(세션 만료) 수집을 멈추고, 다시 로그인한 뒤 이어서 수집할지 묻습니다. 그때까지 모은 메뉴는 남습니다.

**스크립트 메뉴 · 팝업**
- 은행·공공 사이트에 많은 `javascript:` 메뉴(주소 없이 스크립트로 이동)는 **사람이 누르듯 하나씩 눌러** 열리는 화면을 확인하고, 그 화면의 탭·선택 항목을 다음 Depth로 읽습니다(예: `Login > Forgot User ID > User ID issued at the branch`). 로그아웃·삭제·해지·취소 같은 이름과 폼 제출 버튼은 누르지 않습니다. 누르지 못한 메뉴는 이름만 '주소 없는 메뉴'로 기입 대상에 넣을지 묻습니다.
- **로그인 기능이 맨 앞**입니다. 비밀번호 칸이 있는 로그인 상자의 아이디 찾기·비밀번호 찾기·회원가입 같은 기능을 `Login > …`로 넣고, 진단 시트의 첫 열들에 둡니다.
- 정리 규칙: 하위 메뉴를 묶기만 하는 상위 메뉴 단독 열, 전체메뉴 패널·사이드 메뉴에서 생긴 경로 일부 복사본(`User Guide > …` vs `Customer Center > User Guide > …`), 화면 조작 버튼(`Open Whole Menu`, `전체메뉴`, `닫기` 등)은 넣지 않습니다.
- 메뉴 영역은 `nav`·`gnb`·`lnb` 같은 표준 표시를 먼저 찾고, 없으면 `#menu`·`#topMenu`·`header` 목록 같은 예전 방식도 찾습니다. 그래도 못 찾으면 고급 설정에서 메뉴 영역 CSS 선택자를 지정합니다.
- 브라우저 번역 안내 창은 끄고, 페이지가 스스로 여는 팝업 창은 막거나 닫고, 공지 레이어 팝업은 숨긴 뒤 메뉴를 읽습니다. 로그인 단계에서는 팝업을 건드리지 않습니다.

**이미 받은 메뉴 목록 엑셀로 기입 (다시 수집하지 않음)**

```bat
run.bat --from-result 결과
```

`결과` 폴더의 `*_메뉴목록_*.xlsx`를 모두 읽어, 파일마다 시작 주소를 진단 시트 D6과 비교해 시트를 찾고 하나의 새 진단 엑셀에 기입합니다. 파일 하나나 `결과\*_20261112_*.xlsx` 같은 패턴도 됩니다.

**그 밖의 방법**
- 첫 질문에서 `g` = 구글 시트에 바로 입력([연결 방법](#구글-시트-자동-입력-연결-처음-1회)), `p` = 구글 시트 붙여넣기(붙여넣을 칸 안내 + 클립보드), `-`(지난번 파일이 없으면 Enter) = 기입 없이 수집만.
- 웹 화면이 편하면 `run_web.bat` (보조 실행 방식).
- Windows 콘솔에서 글자가 겹치지 않도록 화면의 특수 기호(`· → ※ …`)는 ASCII로 바꿔 표시합니다. 엑셀에 저장되는 값은 그대로입니다.

### 옵션으로 바로 실행

```bat
run.bat https://www.example.com --mode public --headless -y
run.bat https://www.example.com --mode compare --login-url https://www.example.com/login --username tester
```

주소에 `&`가 들어가면 큰따옴표로 감싸세요. 예: `run.bat "https://site/?a=1&b=2"`. `--mode`는 `public`, `login`, `compare` 중 하나입니다. 그 밖에 `--max-pages`, `--max-seconds`, `--delay-ms`, `--extra-host`, `--selector`, `--out` 옵션이 있으며, 전체 목록은 `run.bat --help`로 확인합니다. 방문 페이지 수와 수집 시간은 기본적으로 **제한 없음(0)**이며, 메뉴를 모두 확인하면 끝납니다. 필요할 때만 `--max-pages 500`처럼 제한을 겁니다.

## 확정된 동작

- DNS 하위도메인 수집이 아닌, `조회 → 계좌조회 → 거래내역` 같은 메뉴 계층 수집입니다.
- **최대 3단계까지만** 매핑합니다. 4단계 이하의 이름·주소는 결과에서 제외하며, 해당 3단계 메뉴를 대표 항목으로 남깁니다.
- 1 Depth만 있는 메뉴도 정상입니다. 2·3 Depth를 억지로 채우지 않습니다.
- 로그인 필요, 접근 실패, 동적 메뉴, 구조 확인 필요 항목을 정상 수집 결과와 구분합니다.
- 결과는 `.xlsx`입니다. 전체 메뉴 목록에는 URL을 함께 보관하지만, 진단 시트 붙여넣기 영역에는 메뉴명만 넣습니다.
- 시트의 반복 메모 대신 상단 안내·상태 열·색상·필터로 구분합니다.

## 진단 시트에 입력 (크롤링 → 결과 엑셀 → 기입)

크롤링이 끝나 결과 엑셀을 저장하면 바로 "어디에 기입할까요?"라고 묻습니다.

```
1) 구글 시트에 붙여넣기   2) 엑셀 파일에 직접 입력   3) 건너뛰기
```

### 1) 구글 시트에 붙여넣기 (작업 중인 진단표가 구글 시트일 때)

1. 구글 시트에서 `파일 → 다운로드 → Microsoft Excel(.xlsx)`로 받은 파일 경로를 입력합니다. 이 파일은 읽기만 하며, 이미 입력된 메뉴와 빈 열을 확인하는 용도입니다. 빈 시트에 넣는다면 Enter로 건너뜁니다.
2. 진단 시트를 고릅니다(번호 `06`이나 이름 일부로도 지정 가능).
3. 프로그램이 붙여넣을 칸을 알려 줍니다. 예: `‘01_사이트A’ 시트의 AI13 칸을 클릭 → Ctrl+V (채워지는 범위 AI13:AP15)`
4. 메뉴는 이미 클립보드에 복사되어 있습니다(Windows). 해당 칸을 누르고 Ctrl+V만 하면 됩니다.

- 시작 칸은 메뉴나 결과가 있는 마지막 열의 다음 열입니다. 기존 메뉴·결과는 덮어쓰지 않습니다.
- 시트에 이미 있는 메뉴 경로는 빼고 붙여넣습니다.
- 붙여넣기 파일(`구글시트붙여넣기_시트_날짜.tsv`)과 `_입력내역.tsv`를 결과 폴더에 남깁니다.

### 2) 엑셀 파일에 직접 입력

진단 엑셀(.xlsx/.xlsm)과 진단 시트를 고르면, 수집한 메뉴를 해당 시트의 13~15행(1·2·3 Depth)에 채운 새 파일을 만듭니다.

- 메뉴명이나 결과가 하나라도 있는 열은 건드리지 않고, 완전히 빈 열(H~IW)에만 입력합니다. 20~67행 결과 칸은 수정하지 않습니다.
- 시트에 이미 있는 메뉴 경로는 건너뜁니다. 입력·건너뜀·칸 부족 메뉴를 열 위치와 함께 `_입력내역.tsv`로 남깁니다.
- 메뉴 구조에서 이름은 확인했지만 로그인 등으로 페이지를 확인하지 못한 메뉴도 넣을지 묻습니다(`--include-unverified`).
- `--sheet`는 시트 이름 전체 대신 번호(`06`)나 이름 일부로도 지정할 수 있습니다.
- 원본은 그대로 두고 `원본이름_메뉴입력_날짜.xlsx`로 저장합니다. 차트·서식·수식·다른 시트는 바이트 단위로 그대로 유지합니다.
- 엑셀은 파일을 열 때 자동으로 다시 계산하고, 구글 시트는 가져올 때 다시 계산합니다.

```bat
run.bat https://www.example.com --mode public --target google --snapshot "다운로드\진단.xlsx" --sheet 01
run.bat https://www.example.com --mode public --workbook "진단.xlsx" --sheet 01_사이트A
run.bat --from-result "결과\사이트_메뉴목록.xlsx" --workbook "진단.xlsx" --sheet 02_사이트B
```

`--from-result`는 크롤링 없이, 이전에 만든 수집 결과 엑셀의 메뉴를 진단 시트에 입력합니다. `--target google|excel`로 기입 방식을 고르고, `--snapshot`은 구글 시트에서 받은 .xlsx 경로입니다.

## 붙여넣기 형식

- 1행은 1 Depth, 2행은 2 Depth, 3행은 3 Depth이고 메뉴는 가로로 나열합니다. 진단표의 H13:15 배치와 같습니다.
- 250개(H~IW열) 단위로 묶음을 나눕니다. 묶음마다 차례로 복사할지 묻습니다.
- `=`, `+`, `-`, `@`로 시작하는 메뉴명은 앞에 `'`를 붙여 수식으로 해석되지 않게 합니다.

## 구글 시트 자동 입력 연결 (처음 1회)

수집기가 진단표 구글 시트에 직접 값을 넣도록 작은 스크립트(웹 앱)를 **한 번만** 배포합니다. 진단표가 바뀌어도 다시 설치하지 않고, 실행할 때 시트 주소만 넣습니다.

1. https://script.google.com 에서 **새 프로젝트**를 만듭니다.
2. `apps_script/MenuImport.gs` 내용을 전부 붙여넣고 저장합니다.
3. 함수 목록에서 `setup`을 선택해 실행합니다. 권한(구글 시트 보기·수정)을 승인하면 실행 로그에 **연결 키**가 나옵니다.
4. `배포 → 새 배포 → 웹 앱`, 실행 사용자 `나`, 액세스 권한 `모든 사용자` → 배포 → **웹 앱 URL** 복사
5. `run.bat --connect-google` 실행 → 웹 앱 URL과 연결 키 입력. 연결 정보는 이 PC의 `google_sheet.json`에만 저장합니다.

이후 `run.bat` 첫 질문에서 Enter → **진단표 구글 시트 주소**(브라우저 주소창의 `https://docs.google.com/spreadsheets/d/…`)를 붙여넣습니다. 다음 실행부터는 Enter로 지난번 시트를 씁니다. `--sheet-url`로도 지정할 수 있습니다.

- 입력 전에 위치(예: `I13:K15`)를 보여 주고 확인을 받습니다. 13~15행 메뉴 칸에 **값만** 넣고(`'` 접두로 수식·숫자·날짜 변환 없이), 마지막으로 쓴 열 다음부터 채웁니다. 결과 칸, 수식 칸, 병합 셀, 숨긴 열, 숨긴 시트, 서식은 건드리지 않습니다. 여러 명이 동시에 입력해도 잠금으로 겹치지 않습니다.
- 스크립트는 **배포한 계정의 권한**으로 시트를 엽니다. 그 계정이 편집할 수 있는 진단표만 됩니다. 팀 진단표가 다른 계정 소유여도 '링크가 있는 모든 사용자: 편집자'로 공유돼 있거나 배포 계정이 편집자로 추가돼 있으면 **팀 진단표 주소를 바로 넣어** 직접 기입합니다(내 시트에 받았다가 옮길 필요 없음). 변경 기록에는 배포한 계정으로 남습니다.
- 기입 전에 시트의 A13~A15가 1·2·3 Depth 행인지 확인합니다. 양식이 다르면 아무것도 쓰지 않습니다.
- **계정이 여러 개면**(개인 계정, 회사 계정) 계정마다 한 번씩 배포하고 `run.bat --connect-google`로 각각 추가합니다(이름을 붙여 저장, `d1`처럼 삭제). 시트를 처음 쓸 때 어떤 연결로 쓸지 고르면 그 시트는 **그 연결로만** 씁니다. 다른 계정으로 시도하지 않습니다.
- **팀원 사용**: 팀원마다 자기 계정으로 배포·연결하는 것을 권장합니다(변경 기록에 각자 이름이 남고, 연결 키를 나눌 필요가 없음). 한 배포를 같이 쓰려면 웹 앱 URL과 연결 키를 팀 안에서만 공유합니다. 이때 모든 입력은 배포한 계정 이름으로 남고, 키를 가진 사람은 그 계정이 편집할 수 있는 진단표의 메뉴 칸에 값을 넣을 수 있습니다.
- 연결 키를 아는 사람은 메뉴 칸에 값을 넣을 수 있으므로 공유하지 않습니다. 바꾸려면 `resetToken` 실행 후 다시 연결합니다.
- 진단표 안(확장 프로그램 → Apps Script)에 넣어도 됩니다. 그때는 주소를 비워 두면 그 진단표가 기본값입니다.
- 회사 Google Workspace 정책으로 '모든 사용자' 배포가 막혀 있으면 엑셀 파일 입력이나 붙여넣기(`p`)를 씁니다.

## 엑셀 구성

| 시트 | 내용 |
|---|---|
| `수집요약` | 수집 범위, 시간, 상태, 메뉴 수, 제한 도달 여부, 결과 해석 |
| `전체메뉴` | 1·2·3 Depth, 경로, URL, 발견 근거, 수집 상태, 페이지 제목 |
| `미수집_확인필요` | 로그인·권한·접속 문제, 동적 동작 및 메뉴 단계 확인 대상 |
| `방문기록` | 방문 주소, 최종 주소, HTTP 상태, 오류 사유 |
| `로그인후_전용메뉴` | 비교 수집일 때만 생성. 로그인 후에만 발견된 메뉴 |
| `진단메뉴_01` 이후 | H13부터 15행까지 3개 메뉴 단계. 250개씩 묶어서 생성 |

진단 메뉴는 기존 진단 시트의 **H13 셀에 값으로 붙여넣는 형식**입니다. 250개 초과 항목은 다음 묶음으로 내보내며 조용히 잘라내지 않습니다. 사용자가 검토·수정한 메뉴명은 붙여넣기 시트에 반영하고, 전체메뉴 시트에는 수집 원본을 보존합니다.

## 개발 환경과 검증

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m playwright install chromium
.venv/bin/python -m pytest -q
```

설치된 Chromium 버전이 Playwright와 맞지 않으면 `MENU_CRAWLER_BROWSER_PATH`에 Chromium 실행 파일 경로를 지정합니다. 이 값은 테스트와 프로그램의 `chromium` 브라우저 선택에 함께 적용됩니다.

## 수집 범위를 읽는 법

관찰한 화면과 링크에 나타나는 메뉴를 수집합니다. 로그인·권한 때문에 나타나지 않은 메뉴는 정확한 이름을 알 수 없으므로 **해당 페이지 단위의 미수집 사유**를 기록합니다. 탐색 종료를 사이트 전체 메뉴의 완전한 수집으로 표시하지 않습니다.

실제 메뉴 구조를 알 수 없는 본문 링크는 자동 확정하지 않고 검토 대상으로 둡니다. 로그인 정보 저장·공유 기능은 구현하지 않았으며, 브라우저 세션은 실행 중 메모리에서 사용합니다. 임의의 업무 버튼 클릭이나 폼 제출은 자동화하지 않습니다.
